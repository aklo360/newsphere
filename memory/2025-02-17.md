## Session 3: Deep Iteration Learnings (NOX Brand)

### Icon Design Process
**ACP pipeline is FULLY AUTONOMOUS — runs end-to-end without human approval.**

#### What Worked:
- Simple crescent moon + few subtle circuit lines (3-4 thin traces, small nodes)
- Robotic/AI owl face (geometric, camera-lens eyes, minimal)
- Hexagon with integrated N letterform (bold strokes, interlocking segments)

#### What Failed:
- Dense circuit board patterns (too busy)
- Plain shapes with no detail (too boring)
- Combining 3+ concepts (owl + moon + circuits + stars = disaster)
- Cute/organic owl faces (need geometric/tech aesthetic)

#### The Sweet Spot:
- ONE main shape + ONE subtle detail
- "Can describe in one sentence" test
- Example: "Crescent moon with a few circuit traces inside"

### Banner/Avatar Critical Rules

**🔴 CONTRAST IS KING:**
- Icon on dark background MUST be BRIGHT (white/cyan/neon glow)
- NEVER dark icon on dark background
- Avatar and banner backgrounds should MATCH in style/palette

**🔴 QUALITY PROMPTING:**
- Explicitly say "ULTRA PREMIUM" or "4K QUALITY" or "HIGH FIDELITY"
- Say "SHARP, CRISP, no blur, no artifacts"
- Without these, outputs feel low-res

**🔴 Cyberpunk City Banner Formula (OPTIONAL — only if user asks or concept demands):**
```
Background: subtle cyberpunk cityscape silhouette along bottom,
neon-lit skyscrapers, dark sky with purple/cyan gradient glow.
Icon: BRIGHT GLOWING neon (cyan/purple).
Wordmark: crisp white with subtle glow.
```

### Frame Fill (FINAL)
- **Target: 60-70%** (not 85% which is too cramped)
- ~15% padding on each side
- Icon should feel substantial but have breathing room

### Process Learnings
1. Analyze concept → generate icon → generate lockups → generate socials → upload → deliver
2. Only run full pipeline after "yes"
3. Use reasoning mode (`/reasoning on`) for complex design work
4. After 10+ compactions, quality degrades — start fresh session
5. Save learnings to memory BEFORE context rots

## Session 4: x402 Payment Gateway Integration

### Implementation Complete
Cloned OpenVid gateway architecture to OpenGFX for multi-chain crypto payments.

**Commit:** `3d40274` — "Add x402 Payment Gateway"

### Gateway Structure
```
gateway/
├── package.json         # @opengfx/gateway v1.0.0
├── tsconfig.json
├── .env.example         # Wallet config template
└── src/
    ├── server.ts        # Main Express server (27KB)
    ├── jobs.ts          # Job queue management
    ├── settlement.ts    # Base USDC (EIP-3009)
    ├── settlement-solana.ts  # Solana SOL/USDC
    └── price-feed.ts    # Pyth SOL/USD feed
```

### API Endpoints
| Endpoint | Service | Price |
|----------|---------|-------|
| `POST /v1/logo` | Logo System | $15 |
| `POST /v1/socials` | Social Assets | $10 |
| `POST /v1/brand` | Full Brand | $20 |
| `GET /v1/jobs/:id` | Job Status | - |
| `GET /v1/pricing` | Price Info | - |

### Supported Chains
- **Base USDC** — EIP-3009 transferWithAuthorization
- **Solana USDC** — SPL token transfer
- **Solana SOL** — Native transfer (Pyth price feed for USD conversion)

### Payment Flow
1. POST request → 402 with payment options (all chains)
2. Client signs payment, retries with X-Payment header
3. Server returns jobId immediately
4. Client polls `/v1/jobs/:id` for completion
5. Response contains CDN URLs for all assets

### Key Features
- Async job processing with background generation
- Step progress tracking (analyzing → icon → wordmark → lockups → styleguide)
- Solana: immediate settlement (blockhash expiry)
- EVM: settlement after generation
- Job persistence via API with local fallback
- SOL price caching (30s TTL, Pyth primary, CoinGecko fallback)

### Running
```bash
cd gateway
cp .env.example .env   # Configure wallet addresses
npm run dev            # Development (port 4022)
npm start              # Production
```
